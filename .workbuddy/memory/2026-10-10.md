## 拉取云端修改 + 修复损坏的本地仓库

### 背景
用户要求"拉取云端的修改"。发现本地仓库已损坏。

### 问题诊断
1. 本地 `.git` 损坏：
   - `refs/` 目录丢失（HEAD 指向 `refs/heads/main` 但找不到）
   - `packed-refs` 里只有 `origin/main`，无 `refs/heads/main`
   - 初始 clone 的 50MB pack 不完整（指向 `38fbc47` 等新对象报错 `unable to read e1bbc7ba...`）
2. 本地有未推送的 commit：51e...（CDN 本地化修复，8月2日创建但从未 push 成功）
3. 网络直连 GitHub 不稳定：`git clone` 完整仓库（50MB pack）时 `Connection was reset`，反复失败

### 解决步骤
1. **浅克隆成功**：`git clone --depth 1` 只下载最新快照（pack 小，5秒完成，未被重置）
2. **合并本地改动**：把原目录（工作区文件完好）的以下文件拷到浅克隆：
   - `index.html`（CDN 本地化版：删 Google Fonts/MathJax、bootstrap-icons 改本地引用）
   - `static/css/bootstrap-icons.css`、`static/fonts/*`（本地化字体）
   - `contents/Work.md`（未提交改动）
3. **重新应用 CDN 本地化**到浅克隆的 index.html（云端版含 campus section，需保留）
4. **重新提交** + **push 成功**：commit `080495c`，云端 `38fbc47..080495c`
5. **同步回原目录**：原目录被占用无法删除/重命名（Windows busy），但可写 → `cp -a` 把浅克隆完整内容（含修复后的 .git）覆盖回原目录
6. 清理临时目录 `.shallow`、`.fresh`

### 关键经验（下次复用）
- 完整 clone 被连接重置时，用 `--depth 1` 浅克隆绕过（pack 体积小不易断）
- Windows 下被 IDE/资源管理器占用的目录：`mv`/`rm` 整目录会报 busy，但**写入/覆盖内容可以** → 用 `cp -a` 覆盖内部文件来"替换"仓库
- 个人主页项目 index.html 的 CDN 依赖（polyfill.io/jsdelivr/Google Fonts/MathJax）在国内被墙会导致白屏，已全部本地化
